🔄 notify-on-pr

Sends notifications when a pull request is opened or updated.

uses: developjik/notify-action-hub/notify-on-pr@v1

Copy the snippet above and paste it into the uses: of your workflow.

GitHub event: pull_request (opened · reopened · synchronize) Slack · Discord · Telegram

Inputs¶

NameRequiredDefaultDescription
slack_webhook_url❌ Optional—Slack Incoming Webhook URL
discord_webhook_url❌ Optional—Discord Incoming Webhook URL
telegram_bot_token❌ Optional—Telegram Bot Token
telegram_chat_id❌ Optional—Telegram Chat ID (Required if using Telegram notifications)
dry_run❌ OptionalfalseLog the payload instead of actually sending it (true/false)
message_prefix❌ Optional—Prefix prepended to the notification message (e.g., project name)

At least one notification channel (Slack, Discord, or Telegram) must be configured. Unconfigured platforms are skipped.

Outputs¶

NameDescription
notification_statusNotification result: sent, partial, failed, dry-run, or skipped
failed_platformsComma-separated list of platforms that failed (empty if none)

Outputs can be referenced in later steps via steps.notify.outputs.*.

Usage example¶

Basic usage

name: PR Notification

on:
  pull_request:
    types: [opened, reopened, synchronize]

jobs:
  notify:
    runs-on: ubuntu-latest
    steps:
      - name: Send PR Notification
        id: notify
        uses: developjik/notify-action-hub/notify-on-pr@v1
        with:
          slack_webhook_url: ${{ secrets.SLACK_WEBHOOK_URL }}
          discord_webhook_url: ${{ secrets.DISCORD_WEBHOOK_URL }}
          telegram_bot_token: ${{ secrets.TELEGRAM_BOT_TOKEN }}
          telegram_chat_id: ${{ secrets.TELEGRAM_CHAT_ID }}

Using outputs in a later step

- name: Check notification result
  if: ${{ steps.notify.outputs.notification_status == 'partial' }}
  run: echo "failed_platforms = ${{ steps.notify.outputs.failed_platforms }}"
